Привет) Во вторник ты всех обрадовал тем, что можно реализовать все паттерны по отдельности. Я начала делать дз до нашего вторничного созвона, поэтому держи монстра, в котором все паттерны связаны в единой программе.
Чтобы было проще во всем этом разобраться, я написала небольшую инструкцию.
Общая идея программы:
-Есть продукты(класс Product);
-Есть несколько способов оплаты(они собраны в папке pay);
-Несколько продуктов можно объединить в один заказ(класс Order). 

1. Покупатель выбирает способ оплаты OrderPayment- CardPayment, CashPayment, QRPayment. 
Здесь у нас реализован паттерн стратегия - три класса по своему реализуют один интерфейс.
2.  Покупатель добавляет продукты в List. Список продуктов проверяется на корректность. Это реализовано с помощью класса CheckHandler  и его наследников - PriceCheckHandler, ProductCheckHandler, StockCheckHandler. Здесь я реализовала проверки всех полей продукта, чтобы не продать пустой или несуществующий товар. Это реализация паттерна цепочка событий
3. Создается заказ. В нем есть обязательные поля - список товаров и способ оплаты. Остальные опциональные. Чтобы не создавать несколько конструкторов, реализован класс OrderBuilder - паттерн билдер. Я сделала его вложенным, потому что он напрямую связан с классом Order и создает экземпляр этого класса.
Кстати, цепочка событий тоже собирается через билдер. Здесь класс отдельный, а не вложенный - он не привязан ни к какому определенному хендлеру, а собирает другие хендлеры в цепочку.
4. Чтобы оплата не происходила напрямую, создан класс PaymentProxy - паттерн прокси. В реальной жизни оплата никогда не происходит напрямую, всегда нужно произвести несколько проверок. Самую простую я реализовала у себя.
5. При оплате можно применять разные бонусы, скидки. Подобные механизмы можно добавлять через декоратор - я его реализовала в классе PaymentDecorator. Его наследники ComissionDecorator и DiscountDecorator могут производить различные действия с входными данными(рассчитывать скидку, начислять комиссию).
6. Добавила старый класс для оплаты - OldPayment. чтобы оплата происходила корректно написала адаптер OldPaymentAdapter.
